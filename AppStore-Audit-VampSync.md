# Vamp Sync Mac App Store audit

Audited 23 October 2026. App record **6762657715**, bundle **com.mesutcy.remotedesktop.host**, scheme **VampSyncAppStore**, version **4.0.0**, build **78**. The listing and installed app use **Vamp Sync**. The existing host identity, trust, session, and journal paths are retained.

The screen-lock code issue and legacy-IAP review notes are fixed in build 78. The signed package and automated tests pass. **Functional release sign-off remains open** for real TestFlight streaming and upgrade tests. Successful upload/processing does not establish App Review approval.

| Finding | Result and action |
| --- | --- |
| Undocumented screen-lock dependency | **Fixed in build 78.** Store compilation uses documented NSWorkspace session/display notifications, public CGSession on-console/login-complete keys, and CGDisplayIsAsleep. Unknown or inactive snapshots remain unavailable. These signals describe session availability, not exact lock-screen authentication. Remote input and Remote Unlock remain disabled in every Store state, and ScreenCaptureKit controls the available capture frames. Website checks retain their existing behavior behind compilation guards. LoginWindowInputService receives a fresh lock check from the website host rather than embedding the undocumented query in the shared library. Every bundled Mach-O in the archive and exported package passes the new dependency scan; its negative check correctly rejects build 77. |
| App Store screenshots | **Updated and verified.** The 4.0.0 draft now has three current Sync images in each of six locales (18 total), rendered from the production SwiftUI components with fictional device data. Apple reports every asset COMPLETE; dimensions, order, and uploaded file checksums match. Old Host images are backed up under `Screenshots/backup/`. |
| Signed capture and upgrade continuity | **Open release check.** Install build 78 through TestFlight and test Screen Recording, a real paired-client stream, revocation, and upgrade from the released Host with existing trust data. No TCC, identity, or user-data changes were made for this work. |
| Broken edition comparison link | **Fixed and deployed.** The live page lacked `#editions`. The published comparison now distinguishes website controls from the store edition. The exact page and website DMG return HTTP 200. |
| Privacy wording | **Fixed and deployed.** The policy now identifies Sync, explicitly explains the store edition’s View Only restrictions, and distinguishes website Accessibility permission. Its effective date is 23 October 2026. |
| Website-edition promotion | **Implemented.** A card below the store app’s device controls explains keyboard/pointer input, resizing, optional Remote Unlock, and Screen Recording/Accessibility consent. It opens the HTTPS comparison page in the browser. It does not download, install, update, or unlock code in the store app. Review notes disclose the card. Final acceptance remains Apple’s decision. |
| Build delivery | **Uploaded, VALID, App Store Eligible, and selected for 4.0.0.** Build ID `1e5338e1-2e16-4b18-8d8b-42e7d69fc649`. Build 78 uses stable Xcode 27.1 build 27A9275 and the existing publisher's distribution identity/profile. Signing, embedded profile, installer signature, sandbox, app identity, updater absence, and final payload checks pass. The version remains Prepare for Submission with manual release; App Review was not submitted. |
| Legacy in-app purchase | **Review notes fixed and read back exactly.** The notes explicitly identify “Unlimited Usage-Mac Full Unlock” (`mesut.buu.player.macunlock1`) as unused legacy configuration, unavailable and unnecessary in Vamp Sync, and not attached to this submission. All submitted View Only features work without a purchase; no purchase flow exists for review. The IAP itself remains Ready to Submit and was not modified or submitted. Its generic CLI warning does not require adding it to this release. |
| Account-only checks | **Reverified in the authenticated App Store Connect UI on 23 October.** Data Not Collected is published; the privacy URL is `https://thevamp.app/privacy/`. Both Free Apps and Paid Apps agreements are Active for 13 October 2026–19 February 2027. Digital Services Act status is Active; this app currently declares non-trader status. No agreement or declaration was changed. The CLI web-session cache remains expired, so its deep-check warning is a tooling limitation covered by these manual observations. |
| Focused-client network rule | **Related client review risk.** Guideline 4.2.7(a) specifies a local LAN for focused remote-desktop clients. A private Tailscale tunnel does not establish that condition. This rule addresses the receiving client, rather than automatically disqualifying this macOS host. App Stream's remote-tailnet behavior therefore needs its own review assessment; the current host notes disclose Tailscale honestly. |
| Metadata hygiene | **Non-blocking.** The CLI flags keywords repeating subtitle terms in five locales. Required metadata, review contact, age rating, pricing/availability, and selected build checks pass. |

Apple requires accurate metadata and app-in-use screenshots, sandboxed self-contained Mac packages, Mac App Store updates, public APIs, and recording consent. The edition card opens a separate app's informational website and performs no installation or in-app unlock. It still carries reviewer discretion under the Mac distribution and minimum-functionality rules. See [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/), particularly 2.1(b), 2.3, 2.4.5, 2.5.1, 2.5.14, 4.2.2, and 4.2.7. Apple's [CGSessionCopyCurrentDictionary documentation](https://developer.apple.com/documentation/coregraphics/cgsessioncopycurrentdictionary()) documents the function; the raw lock key is now retained only in website compilation.

Verified controls and evidence:

- The store policy enforces View Only and blocks Accessibility requests, input injection, Remote Unlock, app management, window resizing, terminals, and browser control. The existing signed pairing, fingerprint approval, authenticated session checks, and replay protections remain in place.
- **690 Swift tests and 24 Linux host tests passed**, including four new session-availability tests and existing runtime-policy, pairing, routing, and Remote Unlock safety tests. The new tests cover unknown snapshots, inactive sessions surviving wake events, and independent screen/system sleep restrictions. The finalized availability tests were also rerun successfully. Both Sync editions, Vamp Stream iOS, Vamp Control iOS, and Vamp Control macOS built; the final Store archive and exported package passed verification with stable Xcode.
- The exported package has a valid installer signature, matching unexpired embedded Mac App Store distribution profile, correct host bundle ID, and sandbox/network entitlements. No Sparkle components or private-framework linkage were found in the inspected package build.
- After selecting build 78, fresh `asc validate --check-urls` and `asc review doctor` both report **0 errors, 6 warnings, 2 infos, 0 blocking checks**. The warnings remain the unused legacy IAP and five keyword overlaps. The two infos concern manual release and API-only privacy coverage; privacy publication was separately confirmed in the authenticated UI. The IAP warning is addressed in the reviewer notes without submitting an unused purchase.
- The final readback reverified all **18 screenshots** as COMPLETE, with exact local checksums, correct order, and 2560×1600 dimensions across six locales. Build 78 does not alter the photographed UI.
- Static link validation checked **10 pages and 31 download/checksum URLs with zero errors**. Live comparison, privacy, and DMG checks passed. [Website change](https://github.com/Mesutcydev/vamp-suite/commit/e7cdf9008457145fc5f4d7f39887143eda58f0ab) and [successful deployment](https://github.com/Mesutcydev/vamp-suite/actions/runs/39918949403).
