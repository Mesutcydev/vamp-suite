# Governance

Vamp Terminal is a maintainer-led open-source project.

## Roles

- **Contributors** submit issues, documentation, code, tests, translations, or
  reviews under the project contribution terms.
- **Reviewers** are trusted contributors who regularly review an area of the code.
- **Maintainers** merge changes, manage releases, set repository policy, and respond
  to security reports.

The current maintainers are listed in [MAINTAINERS.md](MAINTAINERS.md).

## Decisions

Routine decisions are made through issues and pull requests. Maintainers seek rough
consensus, with security, user safety, compatibility, and maintainability taking
priority. If consensus cannot be reached, the maintainers make and document the
decision. Material changes to the trust model, license, telemetry, network design,
or governance require a public proposal and a reasonable comment period.

Security embargoes and reports containing private information are handled privately
under [SECURITY.md](SECURITY.md).

## Becoming a maintainer

A contributor may be invited after sustained, constructive work; reliable review;
sound security judgment; and adherence to the Code of Conduct. Existing maintainers
approve additions. Maintainers may step down at any time and may be removed for
prolonged inactivity, repeated policy violations, or loss of project trust.

## Project continuity

At least two active maintainers should hold release and repository administration
access once the contributor base permits it. Release credentials must never be
shared through the repository. A departing sole maintainer should transfer
repository, domain, update-signing, and security-contact access to a documented
successor or clearly archive the project.

## Amendments

Governance changes are made by pull request and recorded in the repository history.
